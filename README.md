# RP2350 coordinated stepper controller

> **Work in progress.** Firmware runs on a Raspberry Pi Pico 2 bench setup.
> The custom board designs are an **unreviewed feasibility first pass**:
> schematics only, no PCB layout, not checked against datasheets or built.
> Don't fabricate them as-is.

A very low-cost, compact controller for up to **10 small stepper motors** (8 mm
micro steppers, 28BYJ-48 converted to bipolar, about 0.2 A per coil or less).
It's aimed at kinetic art first, then lab and robotics use.

There are no stepper-driver ICs. The RP2350 generates sine-PWM microstepping
itself (voltage mode), using PIO state machines fed by DMA, into cheap
DRV8833-class dual H-bridges (AT8833).

What works today (measured on a Pico 2 + DRV8833 + 8 mm stepper):

- **PWM:** 20 kHz, four-segment H-bridge PWM with slow-decay brake off-time and 1/256-step sine microstepping. Duties below the driver's 0.5 µs minimum pulse are error-diffused.
- **10 axes:** each has its own position, velocity or jog mode on a 1 kHz trajectory tick. Moves use a retargetable trapezoid that lands exactly on the target. Drive amplitude depends on speed, with lower holding current at standstill. Core 1 is about 32% loaded, core 0 about 0.5%.
- **Safety:** an e-stop or driver fault on the analog ladder cuts all outputs in about 30 µs. A watchdog on core 0 drops outputs to coast if core 1 stalls.
- **Status LEDs:** a WS2812 chain shows overall status plus each axis's speed and direction.

## Building the firmware

Requirements:
- [Pico SDK](https://github.com/raspberrypi/pico-sdk) 2.1.1 (set `PICO_SDK_PATH`);
- an `arm-none-eabi` GCC toolchain;
- CMake and Ninja.

```bash
# Custom RP2354B controller (default board)
cmake -S firmware -B firmware/build -G Ninja
cmake --build firmware/build

# Raspberry Pi Pico 2 bench setup
cmake -S firmware -B firmware/build-pico2 -G Ninja -DPICO_BOARD=pico2
cmake --build firmware/build-pico2
```

Options: `-DNUM_MOTORS=1..10` (default 10), `-DLADDER_BYPASS=ON` (bench without
a ladder wired; never use with motors you can't stop by hand), `-DBOOT_TRACE=ON`.

Flash by copying `stepper.uf2` to the board in BOOTSEL mode, or with picotool:

```bash
picotool load -x firmware/build-pico2/stepper.uf2
```

Host tests (no hardware needed):

```bash
cd firmware/test
cc -std=c11 -O1 -Wall -Wextra -I../src test_host.c ../src/hbridge_encode.c \
   ../src/microstep.c ../src/sine_lut.c ../src/ladder.c ../src/motion.c -lm -o test_host && ./test_host
```

## Pico 2 bench setup

| Pico 2 | Connects to |
|---|---|
| GP0-GP3 | motor 1: DRV8833 module AIN1, AIN2, BIN1, BIN2 (motors 2-5 on GP4-GP19) |
| GP20 | WS2812 chain data in (pixel 0 status, pixels 1-10 axes) |
| GP26 | ladder: 10k to 3V3, 20k to GND (idle); see [hardware/README.md](hardware/README.md) |
| GP28 | board ID (optional) |
| VBUS / GND | DRV8833 VM and GND; pull the module's sleep pin (EEP) high |

Motors 6-10 have no pins on the Pico 2, but their state machines and DMA still
run, so the full 10-axis load is exercised.

The USB serial console takes line commands (type `help`). Some examples:

```
m 1 500          move axis 1 to 500 full steps
mr * -100        move every axis back 100 steps
j 3 400          jog axis 3 at 400 steps/s (stops unless repeated within 300 ms)
lim 1 1200 4000  axis 1 limits: 1200 steps/s, 4000 steps/s^2
t 100            100 telemetry lines/s: T <tick> then position, speed per axis
?                status, loads and per-axis table
```

## Notes

- **Sine table:** the SDK's float `sinf` returned wrong values near multiples
  of π/2 on the RP2350, which produced reverse pulses at each coil peak. The
  sine table is generated offline (`firmware/tools/gen_sine_lut.py`) instead.
- **Endless DMA:** on the RP2350, endless-mode DMA (`TRANS_COUNT` mode 0xF)
  still needs a non-zero count, or the channel completes immediately.
